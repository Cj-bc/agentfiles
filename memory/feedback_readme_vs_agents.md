README には、恒久的に残るエンドユーザー向けの内容だけを書く。

**Why:** 2026-10-22、tmp-budget-book の PR で、ワークフローの説明（署名・キャッシュ・バージョンの決め方など）と「オーナーが準備すること」（今回のタスクの手順）を README に追記したところ、オーナーから指摘された。
「今回のタスクに関する開発者への指示は README に不要」「agent 向けの情報は README に不要。残したいなら AGENTS.md に」「読めばわかる情報は削って」。

**How to apply:**
- タスクの手順（GitHub の設定、Secrets の登録など）は PR の説明か issue に書き、README には書かない。
- 実装の理由や注意をドキュメントに残したくなったら、まずコードのコメントで足りないかを考える。足りず、エージェントが知るべきことなら AGENTS.md に書く。
- AGENTS.md にも、コードを読めば分かることは書かない（例: 「署名は環境変数から」）。書くのは、読んでも分からない理由や罠だけ（例: 「再利用可能なワークフローに戻すと Secrets が空になる」）。
- issue に「README に追記する」とあっても、中身が上の基準に合うかを確かめる（今回の issue にはそうあったが、オーナーの意図は違った）。
