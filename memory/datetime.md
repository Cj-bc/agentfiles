## 4桁年に制限するときは、UTC の範囲を前後1日ずつ内側に寄せる
「年を -9999〜9999 に収める」という制約を **UTC の瞬間（instant）** に課すときは、
素直に `-9999-01-01T00:00:00Z` 〜 `9999-12-31T23:59:59.999999999Z` にしてはいけない。
UTC オフセットを適用した瞬間に範囲外の年が出るため。

- `-9999-01-01T00:00:00Z` を正のオフセットで読むと年 **-10000**
- `9999-12-31T23:59:59Z` を負のオフセットで読むと年 **10000**

実在するオフセットは ±18:00 以内なので、**両端を 1 日ずつ内側に寄せれば足りる**:

| | 日付 | epoch からの秒 | `nano` |
| --- | --- | --- | --- |
| min | `-9999-01-02T00:00:00Z` | `-377_705_116_800` | `0` |
| max | `9999-12-30T23:59:59.999999999Z` | `253_402_214_399` | `999_999_999` |

`01-02` / `12-30` という一見中途半端な日付はこの理由。仕様に書かれていないと必ず「なぜ 01-01 じゃないのか」を聞かれるので、
定数のドキュメントコメントに理由を書く。同じ考え方は Java の `OffsetDateTime` や ECMAScript Temporal にもある。

## 境界秒は proleptic Gregorian の日数から出す
Python の `datetime` は **year 1〜9999 しか扱えない** ので、年 -9999 の計算には使えない。
Howard Hinnant の `days_from_civil` を書いて日数を出し、`* 86400` する（閏秒はモデル化しない）。

```python
def days_from_civil(y, m, d):          # 1970-01-01 = 0
    y -= m <= 2
    era = (y if y >= 0 else y - 399) // 400
    yoe = y - era * 400
    doy = (153 * (m + (-3 if m > 2 else 9)) + 2) // 5 + d - 1
    doe = yoe * 365 + yoe // 4 - yoe // 100 + doy
    return era * 146097 + doe - 719468
```

`days_from_civil(-9999, 1, 1) = -4371588`、`days_from_civil(9999, 12, 31) = 2932896`。
テスト側にはこの **日数** を定数として置き、両端は `(-4371588 + 1) * 86400` のように導出させる。
実装からコピーした秒数を期待値に書くと、テストが「カレンダー上の主張」ではなく「実装の写経」になる。

## 範囲を狭めても、オーバーフローガードは消さない
「新しい範囲では `Int64` は絶対に溢れない」からといって既存のガードを消すと、
**範囲外の値を作れる入口が 1 つでも残っていれば静かに壊れる**。
Flix の `pub enum Instant({secondsSinceEpoch = Int64, nano = Int32})` はコンストラクタが公開なので、
利用者は範囲外の `Instant` を組み立てられる。ガードを外すと
`tryAdd(instant(Int64.maxValue(), 0), 1秒)` が桁溢れして **範囲内に巻き戻った値を `Ok` で返す**
（最悪の失敗: 誤った答えを成功として返す）。

不変条件を型で守れない構造なら、ガードは冗長ではない。**冗長に見える理由をコメントに書いて残す**。

## 範囲を狭めたら、すべてのコンストラクタを見直す
引数の型が範囲より広いコンストラクタは、それだけで不変条件の穴になる。

- `fromEpochNanoseconds(Int64)` → `Int64` ns は約 ±292 年ぶんしかないので常に範囲内。対処不要。
- `fromEpochMilliseconds(Int64)` → `Int64` ms は約 ±2.9 億年ぶん。範囲を 4 桁年に絞ると **4 桁ほど外へはみ出す**。

はみ出す側は、そのリポジトリが既に持っている流儀に合わせる。
ここは `tryAdd` / `saturatingAdd` の対があったので、`tryFromEpochMilliseconds`（`Option`）と
`fromEpochMilliseconds`（飽和）の 2 本立てにした。
飽和側を残したおかげで `now(): Instant \ Clock` のシグネチャを変えずに済んでいる
（`Clock` はミリ秒を返すので、`Option` にすると `now()` まで汚染される）。
