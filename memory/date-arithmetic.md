## Python の `days_from_civil` は負の年で1日ずれやすい
Howard Hinnant の C++ 版は `/` が 0 方向への切り捨てなので、負の年を `(y - 399) / 400` で床除算に直している。
Python の `//` はもともと床除算なので、これをそのまま写すと **負の年で二重に切り下げ**、1日ずれる。

```python
era = (y if y >= 0 else y - 399) // 400   # NG: Python では二重に切り下げる
era = y // 400                            # OK
```

正しい値（1970-01-01 = 0、先発グレゴリオ暦、年は天文学的年番号）:

| 日付 | 日数 |
| --- | --- |
| -9999-01-01 | -4371587 |
| 0001-01-01 | -719162 |
| 9999-12-31 | 2932896 |

誤った移植では -9999-01-01 が -4371588（実際は -10000-12-31）になる。paranoid-time.flix ではこの誤った値が
`Instant.min()`（-9999-01-02 のはずが実際は -9999-01-01）とテスト harness の定数に入っていた（2026-09 時点、未修正）。

**境界の日数は総当たりで確かめる**: `sum(366 if leap(y) else 365 for y in range(-9999, 1))` = 3652425 なので、
-9999-01-01 = -719162 - 3652425。0001-01-01 は Python の `date.toordinal()` で確かめられる。
400 年は 146097 日 = ちょうど 20871 週なので、400 年の倍数だけ離れた日は同じ曜日（-9999-01-01 も 0001-01-01 も月曜）。
Kotlin の `kotlinx.datetime.LocalDate(...).toEpochDays()` でも確かめられる（オーナーが Playground で確認した）。

## テストの期待値は、実装と別の計算方法で出す
実装と同じ式で期待値を作ると、同じ誤りが両方に入って緑のままになる。paranoid-time.flix の LocalDate では、
テスト harness の日数を序数日（0001-01-01 を 1 日目として、年・月の日数を足し上げる）で計算させた。
そのおかげで、実装側の `min()` 定数が1日ずれていたのを移植テストが最初の実行で捕まえた。

- harness の計算方法には有効範囲を書いておく（このときは -9999 年以降。-10000 年を渡すと黙って誤った値を返した）。
- 範囲の「幅」のような派生値も手で計算せず、テストで両側（ちょうど / 1つ超え）を確かめる。
  月の幅を 239999 と思い込んでいたが、-9999-01 から 9999-12 までは 19999 年 × 12 − 1 = 239987 だった。
