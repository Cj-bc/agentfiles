name: Review public comments for security-sensitive content
description: PR・issue へのコメントは書き上げたら一度読み直し、Secret の値やその手がかりなどセキュリティに関わる内容は書かない。セッション側でだけ伝え、コメントには「セッションを確認して」とだけ残す
type: feedback
---

PR や issue にコメント（PR の説明、リポジトリに入るメモリも含む）を送る前に、書き上げた文を一度読み直し、セキュリティに関わる内容がないか確かめる。
あれば、その部分はコメントから外して Claude のセッション側でだけ伝え、コメントには「セキュリティに関わる点はセッション側に書いた。確認してください」という旨のメモだけ残す。

**Why:** 2026-10-22、tmp-budget-book の公開 PR で、Actions のログのマスク位置から Secret の値が推測できると報告するコメントに、推測した値そのものを書いてしまった。
オーナーから「ここはパブリックの場所。自ら値をバラさないで」と指摘された。今回はデバッグ用の既知の値だったが、本番用の値の可能性もある。
同じ内容を公開リポジトリの agentfiles のメモリにも書いていた。

**How to apply:**
- 書く前に、Secret の値・値の手がかり（長さや一部、マスクの位置から読める文字列）・内部のホスト名・未修正の脆弱性の再現手順などが入っていないか確かめる。
- リポジトリが公開かどうか（`search_repositories` の `private`）を確かめる。private でも、後で公開されることがある（tmp-budget-book は作業中に公開された）。
- 書いてしまったら、コメントを編集して消し、編集履歴にも残ることをオーナーに伝える（履歴の版はオーナーが削除できる）。自分のブランチのコミットなら履歴から取り除いて force push する。
